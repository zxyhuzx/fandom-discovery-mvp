# 작품·인물 목록을 필요한 만큼 불러오기

2026-11-10 적용. 기존 HTML·JS, Supabase, GitHub → Vercel 배포 구조를 유지합니다. 연구 수집 기능은 중지 상태 그대로입니다.

## 데이터 구조

- `catalog_works`: 정식 이름, 고정 work_key, 한글·영문·일본어·줄임말 별칭, 분류, 노출 여부, 표시 순서.
- `catalog_characters`: 소속 작품/그룹의 work_key, 정식 인물 이름, 별칭, 노출 여부, 순서. 동일 이름이라도 소속 작품으로 구분합니다.
- 기존 공개 이름 자료와 편집 목록을 재사용했습니다. 선택 가능 목록은 작품·그룹 77개, 캐릭터·인물 467명입니다. 아이돌은 방탄소년단·세븐틴·스트레이 키즈 3그룹, 멤버 28명으로 시작합니다. 이전에 숨긴 작품을 자동으로 다시 노출하지 않습니다.
- 기존 구독의 별칭 복원을 위해 숨긴 이름도 DB에 보존합니다. 전체 저장량은 작품/그룹 239개, 인물 1,541명입니다. 공개 이름 자료이며 계정·프로필·연구 응답은 포함하지 않습니다.

추가 아이돌 이름 출처: [BTS 공식 프로필](https://bts.ibighit.com/eng/profile/), [SEVENTEEN 공식 프로필](https://www.pledis.co.kr/artist/detail/seventeen/profile/), [Stray Kids 공식 프로필](https://straykids.jype.com/profile). 사진·로고·소개 글은 가져오지 않았습니다. 기존 이름 자료의 출처·라이선스 공개 페이지를 유지합니다.

## 화면과 요청

- 튜토리얼 분류에서 작품·그룹을 처음 20개만 받고 더 보기로 다음 페이지를 불러옵니다. 선택한 관심사는 다른 페이지·분류로 이동해도 유지됩니다.
- 캐릭터·인물 단계에서는 선택한 작품/그룹만 조건으로 전달하고 최대 40개씩 받습니다. 인원이 많으면 더 보기 또는 검색을 이용합니다. 아이돌·버튜버는 ‘그룹 전체’로 선택할 수도 있습니다.
- 상단 자동완성과 관심사 관리는 서버의 정식 이름·별칭 검색 결과 최대 12개를 사용합니다. 창작자·판매자와 현재 굿즈의 검색은 기존 기능을 함께 사용합니다.
- 입력은 180ms 동안 모아서 요청하고, 동일 요청을 합치며 최대 80개의 요청 결과를 세션 메모리에 캐시합니다. 오래된 응답은 화면을 덮어쓰지 않습니다. 요청은 10초 후 중단되며 실패한 요청은 재시도할 수 있습니다.
- 브라우저에 아직 없는 저장 관심사는 형태를 먼저 읽어 보존한 뒤 `catalog_resolve`로 필요한 이름만 복원합니다. 미리 받지 않은 작품이라고 저장값을 삭제하지 않습니다. 일반 사용자 직접 입력 관심사도 기존 정책을 유지합니다.
- 굿즈 업로드의 작품 자동완성도 20개씩 조회하고, 제출한 작품·인물의 별칭을 해당 항목만 확인합니다.

`catalog_search`는 공개 조회 전용 Supabase RPC입니다. 정규화 문자열 검색에 trigram GIN 인덱스, 분류·작품별 탐색 인덱스를 적용했습니다. 한 번에 1~40개, 입력 120자, 검색어 10개, 작품 조건 100개, offset 최대 10,000으로 제한합니다. 대규모 확장 시 실측하여 커서 페이지 방식으로 전환할 수 있습니다. 짧은 한두 글자 검색은 인덱스 효과가 제한적이며 데이터가 커진 뒤 실제 성능 측정이 필요합니다.

운영자만 수정할 수 있고 anon/authenticated는 SELECT만 가능합니다. 함수는 SECURITY INVOKER로 RLS와 조회 권한을 따릅니다. [Supabase DB 함수](https://supabase.com/docs/guides/database/functions), [PostgreSQL pg_trgm](https://www.postgresql.org/docs/17/pgtrgm.html) 기준입니다. 사용자 관심사·프로필·굿즈 권한을 넓히지 않습니다.

## 첫 화면 파일

`catalog-data.js`는 기존 전체 목록을 보존한 시드/오프라인 테스트 소스입니다. 브라우저 빌드는 이를 `catalog-store.js`의 작은 캐시로 대체합니다. 현재 예시 굿즈 표시를 유지하기 위한 7개 작품·22명 이름만 작은 bootstrap에 남깁니다. 나머지는 DB에서 요청한 데이터만 메모리에 들어옵니다.

빌드 검증이 전체 JSON·name-catalog·catalog-data가 브라우저 파일에 포함되면 실패하도록 설정되어 있습니다. 출처 공개용 JSON 다운로드는 사용자가 누를 때만 내려받으며 첫 화면에서 자동으로 불러오지 않습니다. 테마·화면 디자인과 예시 굿즈 80개는 유지합니다.

## 운영·확장

Supabase SQL Editor 또는 기존 관리용 CLI에서 새 카탈로그 행을 추가합니다. 새 그룹은 `catalog_works`, 해당 멤버는 같은 work_key로 `catalog_characters`에 넣습니다. aliases에는 정식 이름과 검색 별칭을 넣고, work_key와 기존 정식 이름은 구독 호환성을 위해 안정적으로 유지하세요. work alias를 변경하면 검색용 자식 정보도 트리거가 갱신합니다. 일반 이용자가 이 표를 직접 수정하는 기능은 없습니다.

이름을 화면에서 숨기려면 active=false를 사용합니다. 기존 구독·굿즈의 이름 해석을 위해 행을 물리 삭제하지 않는 것을 권합니다. 현재 아이돌의 DB 정규화 별칭도 기존 규칙을 보존하며 확장했습니다. 카탈로그만 추가한 경우에도 브라우저가 정식 이름으로 저장하므로 기존 DB 구독·굿즈 매칭 구조를 사용할 수 있습니다.

소스 편집 목록을 다시 반영하려면 기존 마이그레이션을 수정하지 말고 새 파일을 생성하세요.

```sh
node scripts/build-search-catalog.mjs supabase/migrations/새버전_catalog_seed.sql
python3 scripts/db-admin.py apply supabase/migrations/새버전_catalog_seed.sql
```

이 생성기는 이름 자료만 생성합니다. 사용자 관심사·굿즈·연구 데이터는 수정하지 않습니다. 이미 DB에서만 추가한 행을 삭제하지 않습니다. 소스에서 관리되는 기존 행은 갱신하므로 운영 중 편집한 내용과 먼저 비교하세요.

## 검증

```sh
npm test
npm run build
python3 scripts/db-admin.py sql supabase/tests/catalog_integration.sql
npm run test:db
```

새 카탈로그 검증은 롤백하며 실제 참여자나 계정 데이터를 쓰지 않습니다. 별도 브라우저 검증에서 일본어 작품 검색, 히나타 동명이인, 영문 멤버 검색, 페이지 추가 로드, 관심사 저장 후 새로고침, 모바일 표시를 확인했습니다. 실제 기기·대규모 부하 테스트는 별도로 수행해야 합니다. 아이돌의 실제 굿즈 게시물이 없으면 결과가 비어 있을 수 있으며 판매 폼을 임의로 생성하지 않습니다.
